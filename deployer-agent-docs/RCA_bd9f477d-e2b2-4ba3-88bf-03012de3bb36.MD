# RCA — "Chiave IA non configurata" / EMERGENT_LLM_KEY

## Problem statement
User reports AI chat (POST /api/ai/consulente/chat) and AI invoice registration return
`"Chiave IA non configurata sul server: aggiungere EMERGENT_LLM_KEY nel file backend\.env e riavviare i servizi"`.
Need to confirm whether **production on https://fe-fatturazione.emergent.host** is affected, without deploying or changing secrets.

## Verdict
**Production on emergent.host is NOT affected.** The AI chat is working on production. The exact error text the user quoted does **not** exist in the deployed production build — it originates from the self-hosted Windows deployment (invoix.digitalmape.it), which is outside the platform.

## Evidence

### (1) Is EMERGENT_LLM_KEY present & non-empty in production? — YES
`list_secrets` on the active/serving run `bd9f477d-...`:
- `EMERGENT_LLM_KEY` → `is_empty: false`, `metadata_available: true`.
Key is present and non-empty in the production backend environment.

### (2) Does the deployed build contain that EXACT error text? — NO
Active run source (`/app/scratch/backend/ai_agent.py`, lines 19–23):
```python
def _key():
    k = os.environ.get("EMERGENT_LLM_KEY")
    if not k:
        raise HTTPException(500, "Chiave IA non configurata")
    return k
```
- Production raises the **short** message `"Chiave IA non configurata"`.
- The **long** message the user quoted (`...sul server: aggiungere EMERGENT_LLM_KEY nel file backend\.env e riavviare i servizi`) is **absent** from the production source (grep for `riavviare i servizi` / `aggiungere EMERGENT` returned no match in ai_agent.py).
- The only related guidance text in the repo is `server.py:56` referencing the Windows deploy guide: `"Copiate deploy/windows/backend.env.example in backend/.env e compilatelo..."`. This confirms the quoted wording belongs to the Windows self-host path.

### (3) Backend errors in prod logs for /api/ai/consulente/chat? — NONE
`fetch_app_logs` (run bd9f477d, last 1440 min), filter `consulente|EMERGENT_LLM_KEY|Chiave IA|ai_agent|500`:
- Every `POST /api/ai/consulente/chat` → **200 OK** (multiple calls).
- `GET /api/ai/consulente/storico` → 200 OK.
- No 500s, no "Chiave IA" error lines. (The only 404s are `GET /health`, unrelated — that route isn't defined; the Cloudflare/health probe path differs.)

## Root cause
The reported error is produced by the **self-hosted Windows server (invoix.digitalmape.it)**, where `EMERGENT_LLM_KEY` is not set in that host's `backend/.env`. On emergent.host production the key is set and the AI endpoints return 200. The giveaway is the exact message string, which only the Windows deploy guide (not the deployed backend) uses.

## Fix
- No platform action required. Production is healthy.
- If the user wants the self-hosted Windows instance to work, they must set `EMERGENT_LLM_KEY` in `backend/.env` on that Windows server and restart the services (per the deploy/windows guide). That environment is outside the platform and cannot be inspected or changed from here.
